## V3.1 性能測定 — 2026-10-13

51モデルを有効にした旧V3とV3.1を、同じWindowsプロセス・同じ合成入力・dt=0.05秒で比較した。各回15フレームをウォームアップとして除き、旧→新→新→旧の順で各80フレームを測定した。その後、実際の新ホストが使う軽量経路を80フレーム測定した。

| 測定対象 | 平均 | p99 |
|---|---:|---:|
| 旧V3：入力＋51モデル＋全信号JSON | 76.85 ms | 82.83 ms |
| V3.1：入力＋51モデル＋全信号JSON | 52.77 ms | 58.77 ms |
| V3.1：入力＋51モデル＋4更新ごとの軽量監視JSON | 46.41 ms | 52.04 ms |

計算部分だけでは71.28→46.98 ms、約34.1%短縮。ホストが使用する新しい軽量経路と旧経路の平均比較では約39.6%短縮した。軽量経路の監視は最大20Hzのモデルに対する5Hz表示を模擬している。ディスク書き込み、Observerの描画、CSPの処理はこの表に含まない。

モデルの監視データは5,759信号から表示用5信号へ絞り、同じPython JSON表現で249,559→1,735 bytesになった。このサイズはsnapshot部分の比較で、host_idやmanifest等を含むstatus.json全体のサイズではない。51モデル内部の全信号と、検証用の全信号取得APIは維持している。

数値比較は通常fixtureと実験車両のINI設定で各240フレーム・1,382,160信号を検査。最大絶対差はそれぞれ3.83e-12未満、7.28e-12未満。停止・再開、EXE再起動、期限切れ、入力鮮度、checksum、車両ID、軽量APIの同値性も試験した。

## まだ残る制約

これはDLLの模擬試験であり、ゲームFPSは未測定。20Hzの50ms予算に平均は入るが、p99はまだ超える。333Hz相当の追加力制御を可能と認定する結果ではない。参照Luaが持つdt上限、欠損入力、物理出力の単位・座標・重複は別途確認する。

## 実走での比較

同じ車両、コース、天候、描画設定、カメラで、ウォームアップ後にStopを60秒、Resumeを60秒、再びStopを60秒としてフレーム時間を比較する。停止した車での比較と走行中の比較を分ける。平均FPSだけでなく低下時のフレーム時間とNative framesの増加、Model compute、Input sourceも記録する。Stop/Resumeではモデル状態を初期化するため、直後の遷移を別に見る。

再現コマンド：

```powershell
python tests/benchmark_runtime.py --baseline <保存してある旧V3のACNextGenCore.dll>
```

DLLのSHA256と元データはreports/performance_comparison.jsonに記録している。旧バイナリはローカルバックアップに保存し、Gitには含めない。
