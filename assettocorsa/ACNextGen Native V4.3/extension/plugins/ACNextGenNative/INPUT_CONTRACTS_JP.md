# 衝撃・接触入力の接続契約

2026-10-14、インストール済みCSP SDKの`ac_apps/lib.lua`を照合しました。`CarState.acceleration`はG値、車両基準でXが横、Yが上下、Zが前後です。SDKの接地点は世界座標、接触法線は世界方向です。これらの値は描画時点の観測であり、足回り反力の適用時にそのまま使える物理同期値とは扱いません。

元のモジュールと直接接続すると、単位・軸が一致しない箇所があります。

|モジュール|元の参照・解釈|接続方針|
|---|---|---|
|damage_event|accelerationを9.81で除算。X横、Y前後、Z上下|専用のm/s²入力。SDKのX/Z/Yを対応させる|
|impact_sensor|accelerationを9.81で除算。X横、Y前後、Z上下|衝撃イベントと同じ専用変換|
|vehicle_condition|accelerationのノルムを9.81で除算|m/s²。ノルムは軸入替えに不変|
|load_transfer|accelerationのX/Zを横・前後として使用|車両X/Zの加速度。質量・式の単位を確認して接続|
|arm_compliance|acceleration.xを横入力として使用|横軸は一致。係数の単位を確認する|
|road_input_interpreter|Y/Zから上下、Xからピッチ、Zからロール候補を生成|解釈の混在があるため個別校正が必要|

診断開始時の通常EXE入力ではgForcesを渡していましたが、上記が参照するaccelerationは未接続でした。今回、下記の変換層で4モジュールへ接続しました。実車の加速度を受け取っていることと、各モデルへ正しい単位で接続したことを分けて判定します。共通car.accelerationへ一括代入する方式は採用しません。

## 今回実装した観測

Observerの約1秒ごとのログに`input_audit`を追加しました。生のSDK加速度、四輪の接地点・接触法線・車輪位置・荷重・サスペンションストロークを保存します。データ欠落・非有限値は0として補わず、値の欠落として記録します。接触法線が単位ベクトルに近いかを確認しますが、正常な接点座標だけで接地を認定しません。

ObserverのDiagnosticsにも加速度と接触データの取得状態を表示します。入力診断による物理出力の追加・既存演算への転送はありません。読み取り専用の`read_live_telemetry.py`でもOriginal AC共有メモリの加速度・速度・荷重・ストロークを表示できるようにしました。

停止→直進加速・減速→左右旋回の観測で軸と符号を確認し、共有メモリとSDKの値を比較します。異なる更新時点の値なので、時刻・車両・鮮度が一致しない記録を因果的な一致と扱いません。

## 足回りの反力へ進む条件

加速度の各モデル向け変換、荷重と接触情報の鮮度、車輪側APIの単位と反力方向を順に確認します。車体側の力単位Nの検証は済んでいますが、車輪側への反力適用は別の実ゲーム検証が必要です。現在のタイヤ・ヨー補助を基準とし、足回りとLSDの追加出力は校正完了まで有効化しません。


## V4.3 モジュール別変換層

config.jsonのmodel_input_contract=csp_g_v1で有効化します。EXEがOriginal ACの共有メモリから取得したgForcesに、単位g・車両XYZ・出所original_acの契約を添えます。共通Worker経路でも加速度はこの共有メモリ入力です。車両専用cphysの加速度は別の出所として未検証扱いにし、この変換へ流用しません。

damage_eventとimpact_sensorには[X,Z,Y]×9.81を、vehicle_conditionとload_transferには[X,Y,Z]×9.81を渡します。入力を読む各モジュールのinit/update時だけ専用の車両ビューを使用し、ac.getCar()のフォールバックも同じビューに一致させます。処理後に元のビューを復元します。元の共有gForcesと車両状態は書き換えません。

arm_complianceとroad_input_interpreterはpending_calibrationと表示し、加速度を未取得として維持します。単位・軸・出所が欠落した入力、非有限値、40Gを超える未対応値にもaccelerationを補いません。ゼロGの正常値と未取得を区別します。

CLI・DLL設定を省略したoriginalモードは従来の入力を維持します。変換層は元の51モジュールの演算式を変更しません。入力接続と、車輪側への反力・トルクの検証は別工程です。
